Bottom line: the current code does not support the “present samples while next frame reseeds” diagnosis. Don’t add ping-pong images as the first fix. ## 1. The post-mirror transition is not the LLE-black cause

The recorded order is unambiguous:

1. Native→LLE copy is recorded at [vulkan_render_target_cache.cc:3649](<C:/Users/leanerdesigner/Documents/New project 8/xenia-thor/src/xenia/gpu/vulkan/vulkan_render_target_cache.cc:3649>).
2. Only afterward is native transitioned from `TRANSFER_SRC` to `SHADER_READ_ONLY` at [vulkan_render_target_cache.cc:3658](<C:/Users/leanerdesigner/Documents/New project 8/xenia-thor/src/xenia/gpu/vulkan/vulkan_render_target_cache.cc:3658>).
3. That barrier’s `TRANSFER_READ` source scope correctly waits for the mirror’s source read.

Nothing in that barrier touches the LLE image. `VK_IMAGE_USAGE_SAMPLED_BIT` also declares permitted use; it does not execute an operation or zero pixels.

The next seed is not racing the previous gamma sample either. Its barrier uses the tracked `FRAGMENT_SHADER/SHADER_READ` state as the source and `TRANSFER/TRANSFER_WRITE` as the destination at [vulkan_render_target_cache.cc:3582](<C:/Users/leanerdesigner/Documents/New project 8/xenia-thor/src/xenia/gpu/vulkan/vulkan_render_target_cache.cc:3582>). A read→write WAR hazard needs only an execution dependency, and barriers apply to earlier operations submitted to the same queue, including earlier submissions. [Khronos’ synchronization examples](https://github.khronos.org/Vulkan-Site/guide/latest/synchronization_examples.html) explicitly show fragment-sample→write as a WAR dependency, while the [Vulkan synchronization specification](https://docs.vulkan.org/spec/latest/chapters/synchronization.html) says pipeline barriers scope operations submitted earlier/later on the same queue.

`oldLayout=UNDEFINED` is legal and discards the old contents; the following seed copy overwrites the entire native extent using the same `host_extent` used to create it ([creation](<C:/Users/leanerdesigner/Documents/New project 8/xenia-thor/src/xenia/gpu/vulkan/vulkan_render_target_cache.cc:3455>), [copy extent](<C:/Users/leanerdesigner/Documents/New project 8/xenia-thor/src/xenia/gpu/vulkan/vulkan_render_target_cache.cc:3593>)). See the [`VkImageMemoryBarrier` rules](https://docs.vulkan.org/refpages/latest/refpages/source/VkImageMemoryBarrier.html).

I would nevertheless change the reuse transition to use the actual tracked layout:

```cpp
oldLayout = fb->bd_native_color_layout;  // SHADER_READ_ONLY_OPTIMAL
newLayout = VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL;
srcStage = fb->bd_native_color_stage;    // FRAGMENT_SHADER
srcAccess = 0;                           // WAR: execution dependency is enough
dstStage = VK_PIPELINE_STAGE_TRANSFER_BIT;
dstAccess = VK_ACCESS_TRANSFER_WRITE_BIT;
```

That is cleaner for validation and capture tools, but it is not a plausible explanation for an already-recorded LLE mirror turning black.

Therefore, if RenderDoc shows the actual LLE image zero immediately after the mirror-copy event, one of these is true:

- native was already zero before the copy;
- the wrong native/LLE resource or event was inspected;
- the intended producer pass was not the pass actually substituted;
- the copy did not execute as assumed.

## 3. Correct lifetime design

For the current final-present leaf, one image is sufficient:

1. First/reuse seed:

   - LLE actual state → `TRANSFER_SRC`.
   - Native actual state → `TRANSFER_DST`.
   - Copy LLE→native.
   - `TRANSFER_WRITE` → color attachment read/write.

2. Render producer.

3. Validation phase:

   - Native color write → `TRANSFER_SRC`.
   - LLE actual state → `TRANSFER_DST`.
   - Copy native→LLE.
   - Native `TRANSFER_READ` → fragment shader read.

4. Gamma pass samples native.

Once correctness is proven and the producer fully overwrites or has persistent native LOAD semantics:

- remove the seed;
- remove the mirror;
- transition color attachment write directly to shader read;
- publish the generation at the logical resolve;
- skip only that exact LLE resolve/transfer;
- present through an exact sampled view with correct format, swizzle and UV extent.

For the durable generalized HLE, use a submission-retired per-generation pool, not two frame-parity images. Xenia permits three frames in flight at [vulkan_command_processor.h:663](<C:/Users/leanerdesigner/Documents/New project 8/xenia-thor/src/xenia/gpu/vulkan/vulkan_command_processor.h:663>), and a resource may have multiple generations inside one frame. Each slot should carry:

```text
image + attachment/sampled views
allocation_extent + logical_extent
format + samples + resolve/fetch swizzle
layout + last stage/access
generation + frame epoch
last_use_submission
alias-live state
```

A/B frontbuffer addresses are logical aliases, not storage-slot indices. Recycle a slot only after its alias is dead and its last-use submission has completed, or grow the pool. This prevents semantic generation overwrite; it is not needed to repair the proposed same-queue WAR race.

| Probe | Interpretation |

At each stage, inspect four exact RenderDoc events/resources: native immediately before mirror, LLE immediately after mirror, native immediately before gamma draw, and the gamma draw’s bound descriptor resource ID. That will locate the first zero without inference.
